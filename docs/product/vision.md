# 产品愿景

> 状态：草案 · 最后更新：2026-11-25
>
> English: [vision_en.md](vision_en.md)

## 一句话定位

Morfa 是一个 AI 驱动的在线 UI 设计平台：用户用自然语言表达意图，Agent 在结构化设计文档上执行操作，产出可直接编辑、可导出、跨平台访问的界面设计。

## 背景与问题

现有设计工具在三个方向上仍有明显断层：

1. **AI 是外挂而非底座**：多数产品把生成能力做成侧边按钮，生成结果难以精确修改，也无法追踪 Agent 做了哪些操作。
2. **跨平台体验割裂**：桌面端、浏览器、平板各自为政，文件与协作状态不同步，触屏交互常被忽略。
3. **主题与国际化是补丁**：深色模式、语言切换往往在后期追加，导致样式散落、文案硬编码、格式化不一致。

Morfa 希望从第一天就把 Agent、跨平台、主题与 i18n 作为一等能力，而不是后置功能。

## 目标用户

| 用户 | 典型诉求 |
| --- | --- |
| 产品设计师 | 快速探索多个方案，把重复劳动交给 Agent，同时保留精细控制 |
| 独立开发者 / 小型团队 | 在一个工具内完成界面设计与交付，减少设计到代码的损耗 |
| 产品经理 / 创始人 | 用自然语言快速把想法变成可讨论、可演示的界面 |
| 设计系统维护者 | 让 Agent 遵循令牌与组件规范，批量检查与修正界面 |

## 核心价值

1. **Agent 驱动，人来把关**：Agent 能规划并执行多步设计操作；所有变更以可审阅的补丁形式呈现，支持应用、回滚与重放。
2. **结构化设计文档**：设计稿是可版本化的数据（节点树 + 样式 + 令牌），不是不可解析的画布像素，因此可查询、可 diff、可导出。
3. **跨平台一致**：浏览器优先，覆盖桌面、平板与触屏；项目数据云端同步，后续提供桌面客户端。
4. **原生主题与 i18n**：深色 / 浅色主题跟随系统并可手动覆盖；默认简体中文、内置英文，格式化和文案统一管理。
5. **开放与可迁移**：设计数据可导出，避免锁定；部署侧尽量轻量，SQLite 让自托管成为可行选项。

## 产品原则

- **Agent 是合作者，不是黑盒**：每一步工具调用有记录，重要操作默认需要确认。
- **设计即数据**：任何 UI 元素都应能被结构化描述、校验和转换。
- **默认可用**：无 AI 时也能完成基础设计；AI 是增强，不是单点依赖。
- **渐进增强**：从 Web 开始，按需扩展到 PWA、桌面与移动端，而不是同时铺开。
- **可访问性内建**：颜色对比、键盘操作、语义结构与文案长度从设计阶段就考虑。
- **本地优先的隐私观**：用户项目默认私有；是否用于模型训练必须显式选择。

## 非目标（首版）

- 不做通用图像编辑、视频剪辑或 3D 建模。
- 不追求 100% 兼容 Figma / Sketch 文件格式。
- 不自研基础大模型，模型能力通过可替换的提供方接入。
- 不做复杂的企业权限矩阵与审批流（后续按需求引入）。
- 不在首版承诺实时多人协同编辑。

## 成功指标

- **激活**：新用户完成第一个可预览设计的中位时长。
- **Agent 质量**：Agent 任务一次通过率、用户撤销率、平均工具调用轮次。
- **留存**：7 日 / 30 日回访与项目复用率。
- **交付**：导出、分享与预览链接的使用率。
- **体验**：首屏加载、画布交互帧率、主题切换与语言切换的成功率。
- **可访问性**：核心流程的键盘可达性与 WCAG AA 对比度覆盖。

## 开放问题

- 首版画布的技术路线：DOM / SVG / Canvas / WebGL，如何兼顾编辑器能力与 Agent 可操作性？
- 设计文档 schema 的版本演进与迁移策略。
- 实时协作的引入时机与 CRDT 方案取舍。
- 免费额度、模型成本与计费模型。
- 桌面客户端（Tauri 或其他方案）的优先级。
