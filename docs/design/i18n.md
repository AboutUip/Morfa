# 国际化（i18n）规范

> 状态：已实现基础（zh-CN / en-US）· 最后更新：2026-11-25

## 语言策略

| 语言 | BCP 47 | 角色 |
| --- | --- | --- |
| 简体中文 | `zh-CN` | 默认语言、主要创作语言 |
| 英文 | `en-US` | 辅助语言，界面完整覆盖 |

- 默认界面语言为 `zh-CN`，首次访问根据浏览器语言匹配，未匹配到时回退到 `zh-CN`。
- 语言偏好存储在 `localStorage` 的 `morfa.locale`，登录后与用户设置同步。
- 文案缺失时回退到 `zh-CN`，并在开发环境输出警告。
- 新增语言只需新增资源目录与语言元数据，不修改业务组件。

## 技术方案

使用 **i18next + react-i18next**：

- 生态成熟，支持命名空间、插值、复数、上下文与懒加载。
- 与 React 集成良好，可在运行时切换语言而无需刷新。
- 通过 `Intl` 处理日期、数字与相对时间。

当前初始化逻辑位于 `apps/web/src/lib/i18n.ts`，通过 `main.tsx` 在渲染前加载资源；语言检测使用本地存储与浏览器语言，不依赖额外检测插件。

## 资源组织

```text
apps/web/src/locales/
├─ zh-CN/
│  └─ common.json       # 当前：导航、加载、工作区文案
├─ en-US/
│  └─ common.json       # 与 zh-CN 同构
```

当前所有界面文案集中在 `common`（包含加载、项目与认证）。文案增多后可拆分为 `editor`（画布与属性面板）、`agent`（对话与运行状态）、`settings`、`auth` 等命名空间；新增命名空间时必须在两种语言中同时创建，并在 `src/lib/i18n.ts` 中注册。

规则：

- 目录与文件使用 BCP 47 语言标签，大小写保持一致（`zh-CN`、`en-US`）。
- 每种语言的命名空间与键必须一致；CI 中校验键集合是否对齐。
- 键使用语义命名，避免以中文或英文原文作为键。
- 嵌套层级不超过三层，按页面或组件聚合。

示例：

```json
{
  "actions": {
    "save": "保存",
    "cancel": "取消",
    "delete": "删除"
  },
  "project": {
    "create": "新建项目",
    "empty": "还没有项目，先创建一个吧",
    "count": "共 {{count}} 个项目"
  }
}
```

## 文案写法

- 句子完整表达，避免把一句话拆成多段拼接；语序差异由翻译资源承担。
- 变量使用双花括号插值：`{{name}}`，并在资源中保留占位符。
- 复数、性别与上下文使用 i18next 的 `count` / `context` 能力；中文无复数变化，但英文需要正确处理。
- 富文本使用 `<Trans>` 组件，不在翻译中写 HTML 字符串。
- 按钮、标签等短文案尽量动词开头；错误信息说明原因与下一步操作。
- 不在代码中拼接标点、单位与括号，完整句式放入资源。
- 中文与英文之间按产品排版规范留空格；专有名词大小写保持一致（如 GitHub、SQLite、Agent）。

## 格式化

- 日期与时间：`Intl.DateTimeFormat(locale, ...)`，存储始终为 UTC。
- 数字与百分比：`Intl.NumberFormat`。
- 相对时间（“3 分钟前”）：`Intl.RelativeTimeFormat`。
- 货币：`Intl.NumberFormat` + ISO 4217 代码，不硬编码符号。
- 文件大小、快捷键等有地区差异的展示，集中封装在 `lib/format` 中。

## 运行机制

1. 应用启动时读取偏好（本地存储 → 用户设置 → 浏览器语言 → `zh-CN`）。
2. 初始化 i18next，加载默认命名空间；其余命名空间按路由或面板懒加载。
3. 切换语言时更新 i18next 语言、`<html lang>`、页面标题与 `dir`（当前两种语言均为 LTR）。
4. 语言选择与主题选择放在同一设置区域，交互保持一致。

```ts
// 简化示意；完整实现见 apps/web/src/lib/i18n.ts
await i18n.use(initReactI18next).init({
  resources: {
    "zh-CN": { common: zhCN },
    "en-US": { common: enUS },
  },
  lng: detectLocale(), // localStorage -> navigator -> zh-CN
  fallbackLng: "zh-CN",
  supportedLngs: ["zh-CN", "en-US"],
  ns: ["common"],
  defaultNS: "common",
  interpolation: { escapeValue: false },
});
```

## 页面与分享链接

- 编辑器等登录后应用默认不使用语言前缀，语言由偏好决定。
- 公开分享页是否需要 `/{locale}/share/...` 形式，待 SEO 与分享体验评估后决定。
- 生成分享链接时记录创建者语言，仅作为接收者默认值的参考，不强制覆盖。

## 测试清单

- `zh-CN` 与 `en-US` 的键集合完全一致，无遗漏与多余键。
- 切换语言后无需刷新，界面文案、日期、数字同步更新。
- `<html lang>` 与存储的偏好正确。
- 英文长文案在按钮、表格与窄屏下不溢出。
- 缺失键在开发环境有警告，生产环境回退到中文且不崩溃。
- Agent 输出、错误信息与空状态均有对应文案。
