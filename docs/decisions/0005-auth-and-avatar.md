# ADR 0005：账号认证与头像存储

> English: [0005-auth-and-avatar_en.md](0005-auth-and-avatar_en.md)

- 状态：已接受
- 日期：2026-11-25
- 决策者：项目维护者

## 背景

项目页需要一个最小可用的账号系统：

- 支持注册与登录，注册后自动登录；
- 注册需要头像、昵称、登录账号、密码与确认密码；
- 登录账号在平台内唯一；
- 头像只保存文件相对路径，不把二进制写入数据库；
- 当前使用 SQLite，后续可能迁移到 PostgreSQL 或对象存储。

## 决策

1. **后端与数据库**：Fastify 5 + Node.js 原生 `node:sqlite`（WAL），服务启动时执行 SQL 迁移。
2. **登录账号**：转小写后写入 `login_account`，使用 `COLLATE NOCASE UNIQUE` 在数据库层去重，并在注册前预检查。
3. **密码**：`crypto.scrypt` + 16 字节随机盐，存储格式 `scrypt$salt$hash`；比较使用 `timingSafeEqual`。
4. **会话**：32 字节随机令牌写入 `HttpOnly; SameSite=Lax` Cookie；数据库只保存 SHA-256 哈希，有效期 30 天。
5. **头像**：`multipart/form-data` 上传，限制 PNG / JPG / WebP、2 MB，并校验文件签名；文件写入 `data/uploads/avatars/`，数据库只保存 `uploads/avatars/<uuid>.<ext>`。
6. **注册自动登录**：注册事务同时创建用户与会话，响应写入 Cookie，前端直接更新登录态。
7. **弹窗交互**：登录 / 注册使用弹窗，点击蒙版不关闭，只允许右上角关闭按钮退出，避免误触。

## 理由

- 不引入外部身份服务，保持本地开发与自托管简单。
- scrypt 是 Node 内置能力，避免原生密码库的编译与部署问题。
- 数据库存储令牌哈希，泄露数据库时不能直接复用会话。
- 账号唯一性放在数据库约束上，避免仅靠应用层检查产生竞态。
- 头像路径入库、文件落盘，便于未来切换到 S3 兼容存储。

## 后果

正面：

- 认证闭环可独立运行，不依赖第三方服务。
- 密码、会话与上传都有明确的边界与校验。
- 头像不占用数据库体积，读取通过受控路由。

负面 / 限制：

- `node:sqlite` 与本地文件存储只适合单机；多节点部署需要迁移数据库与对象存储。
- 目前没有邮箱验证、找回密码、登录限流、头像更换与账号设置。
- 会话 Cookie 依赖同源部署；跨域部署需重新设计。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| JWT 无状态会话 | 撤销、登出与多设备管理更复杂；当前单机 SQLite 足够 |
| better-sqlite3 + Drizzle | 需要原生模块；启动阶段先用 Node 内置能力减少依赖 |
| 头像 BLOB 入库 | 与「仅相对路径入数据库」要求冲突，数据库体积与备份成本更高 |
| 第三方登录（OAuth） | 首版不需要，增加外部依赖与配置 |
| 注册后手动登录 | 需求明确要求注册自动登录 |

## 后续动作

- 增加登录失败限流、密码重置与邮箱 / 账号验证策略。
- 头像更换时清理旧文件。
- 多节点部署前迁移到 PostgreSQL 与对象存储。
- 为认证 API 增加集成测试与端到端测试。
