# ADR 0001：技术栈选择

> English: [0001-tech-stack_en.md](0001-tech-stack_en.md)

- 状态：已接受
- 日期：2026-11-25
- 决策者：项目维护者

## 背景

Morfa 是 AI 驱动的在线 UI 设计平台，需要：

- 复杂、可交互的编辑器界面，并支持跨平台访问；
- 服务端存储项目与设计文档，编排 Agent 运行；
- 轻量部署，降低早期开发与自托管成本；
- 原生深色 / 浅色主题与中英文国际化。

## 决策

采用以下技术栈：

| 层次 | 选择 |
| --- | --- |
| 前端 | React + TypeScript |
| 前端构建 | Vite（建议，M1 确认） |
| 后端 | Node.js + TypeScript |
| 数据库 | SQLite（WAL 模式） |
| 仓库 | npm workspaces monorepo |

具体依赖版本在搭建应用时锁定；不在初始化阶段引入未经使用的依赖。

## 理由

- **React**：生态成熟，编辑器类应用可复用大量交互与可访问性实践；团队熟悉度高，跨平台（Web、桌面壳、后续移动端）路径清晰。
- **Node.js + TypeScript**：前后端共享类型与 schema，减少契约漂移；异步模型适合流式 Agent 响应。
- **SQLite**：单文件、零运维、事务可靠，适合本地优先与小型部署；通过服务端数据访问层隔离，可在需要时迁移 PostgreSQL。
- **npm workspaces**：随 Node.js 提供，无需额外包管理器；足够支撑当前规模，后续可引入 Turborepo 等编排工具。

## 后果

正面：

- 本地开发启动成本低，无外部数据库依赖。
- 类型与校验逻辑可在前后端复用。
- 单仓库便于统一 lint、测试、文档与版本管理。

负面 / 限制：

- SQLite 单写入者，写事务需短小；高并发或多人实时协作时需要重新评估。
- React 生态选择多，需要明确约定避免风格分裂。
- npm workspaces 在任务编排与增量构建上不如专用工具，规模扩大后可能补充。

## 备选方案

| 方案 | 未采用原因 |
| --- | --- |
| Vue / Svelte | 同样可行，但团队与生态积累更偏向 React |
| Express / Hono | 可在实现阶段重新评估；当前倾向 Fastify，性能与 schema 支持更好 |
| PostgreSQL / MySQL | 运维成本更高，早期收益不足以抵消复杂度 |
| pnpm / Yarn | 能力更强，但 npm workspaces 已满足当前需求，减少工具链依赖 |
| 多仓库拆分 | 早期共享契约频繁变化，单仓库更高效 |

## 后续动作

- M1 锁定依赖版本，补充构建、测试与 Lint 配置。
- 引入数据库访问层时记录 ORM 选型 ADR。
- 当出现多节点部署或写入瓶颈时，评估数据库迁移方案。
